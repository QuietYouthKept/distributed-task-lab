# Wave 2 implementation report

Date: 2026-10-09 (Asia/Shanghai). Scope is the implementation actually present in the Phase 1 worktree; this report does not certify production readiness.

## Implemented in this continuation

- `internal/artifacts/{store,local,s3,keys}.go`: shared Store contract, bounded local/S3 objects, conditional create, integrity metadata/hash checks and typed error classes. `ObjectInfo.Key` is the logical key; bucket/prefix remain backend configuration and do not leak into references.
- `internal/worker/handlers/rag_ingestion_real.go`: input/output Store injection was already present; when the worker is explicitly configured with the S3 backend, the shared Store now supplies both input and output objects.
- `internal/worker/handlers/llm_eval.go`: deterministic shard outputs use Store `Get`/`PutIfAbsent`; reuses are checked against the immutable run/shard identity and return an `artifact://` logical-key reference.
- `internal/worker/handlers/llm_gateway_eval.go`: per-case provider receipts are immutable Store objects, allowing a different worker instance to resume; final JSONL, manifest, summary and failures are conditionally persisted through Store. This remains a gateway integration boundary, not evidence of a real external provider.
- `internal/worker/handlers/strategy_replay.go`: RAG replay's raw report is stored through Store and emits a logical `artifact://` reference.
- `internal/worker/handlers/composite.go`, `cmd/worker/main.go`: deterministic Eval, Gateway Eval, RAG and Replay receive a common Store when S3 is explicitly selected. Startup verifies the bucket. Production admission remains fail-closed.
- Tests cover Store logical keys with prefixes, shared Store reuse across handler instances, Gateway per-case receipt recovery, and rejection of an Eval object whose bytes do not match its immutable execution identity.
- The only fix for the later PostgreSQL Race failure was test-only: `claimOne` now has a bounded 10-second polling window and queries `clock_timestamp()` plus the earliest pending `next_run_at`; production scheduling code was not changed.
- `scripts/dev/check-env.ps1`: Windows PowerShell preflight reports dependency status without printing credential values.
- Follow-up CI/S3 hardening: `.github/workflows/ci.yml` now has a required MinIO contract job pinned to the locally verified image digest; credentials are generated per CI run and are never committed. `internal/artifacts/minio_integration_test.go` no longer falls back to `minioadmin`, and now checks concurrent conflicting writers, missing objects, cancellation, invalid credentials and concurrent identical writers.
- Stable API contract hardening: `api/openapi.json` now declares the required reader/operator/admin role per `/v1` operation, Bearer authentication, 401/403/429 error responses and `Retry-After` for throttling. `TestOpenAPIV1RolesAuthErrorsAndRouteSet` checks exact path/method coverage, unique operation IDs, auth scheme, least required roles and common error envelopes; CI runs this gate explicitly.
- Gateway eval determinism: receipt summaries and cost caps now aggregate case-ID-sorted receipts, so Go map iteration cannot change float rounding or immutable output bytes. The replay test compares the first and subsequent manifest byte-for-byte. The issue was first observed in full Race Evidence run `wave2-20261009T121704030Z-8d389ea2900b`; fix verification so far is targeted Race ×20 only.
- Chaos harness clock-step tolerance: `cmd/chaosmatrix` no longer treats a temporarily future `next_run_at` as an immediate terminal test failure. It polls PostgreSQL eligibility within its existing finite 3-second bound, retaining status/time diagnostics on timeout. The 28/30 failure run remains immutable; local rerun `20261009T122922Z` is 30/30 for all six scenarios.

## Follow-up public-client and tracing work

- `pkg/client/{client,types}.go`: replaced the SDK's exported dependency on `internal/domain` with public API types. This keeps external consumers independent of private implementation packages; no DB/API schema migration is involved. Callers constructing client values use `client.TaskType*`, `client.TaskStatus*`, `TaskPayloadEnvelope`, and `Task`.
- `pkg/client/client_test.go`: expanded stable API error tests for 404/409/429/5xx and transport failure, while retaining auth, idempotency, context cancellation, URL validation, and cursor checks.
- `test/external-client/`: independent Go module imports only `pkg/client` and performs create/get/page against a local HTTP contract fixture. `.github/workflows/ci.yml` runs it under Race in a dedicated job.
- `internal/observability/tracing_test.go`: local OTLP/HTTP receiver decodes the emitted protobuf and verifies `service.name` and the named span; targeted Race ×10 passed. This is a local receiver test, not staging telemetry acceptance.
- `scripts/evidence/collect-wave2.ps1`: collection now records the external-module and OTLP-receiver gates and can identify the explicitly configured MinIO container. `run-wave2-with-ephemeral-minio.ps1` uses only the already cached pinned image, one-run random credentials, no persistent volume, a bounded health check, and removes only its own named container/temp files. Evidence remains append-only.
- `internal/storage/postgres/least_privilege_integration_test.go`: migrations run as the owner in a disposable DB; a random role receives narrow application DML/sequence grants, then exercises enqueue/claim/ACK and audited queue pause/resume. Negative assertions reject DDL, TRUNCATE, hard delete, event/audit rewrite, and cluster role creation. Race ×5 passed locally. It is not a production role bootstrap or hosted-DB certification.
- `cmd/paginationbench`: creates and migrates a disposable PostgreSQL database, loads a deterministic 100k-row fixture, records real `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` plans and local latency samples, traverses every row using repository keyset pagination, and verifies that 50 concurrent newer inserts do not perturb the initial traversal. Benchmark output is kept separately from immutable Evidence runs and is copied/hash-recorded by the Wave 2 collector.
- `internal/storage/postgres/task_repository.go`: keyset continuation now uses PostgreSQL row-value comparison `(created_at, id) < (...)`, equivalent to the descending `(created_at,id)` ordering but eligible for a composite B-tree range scan. A deterministic equal-timestamp regression test checks both page ordering and the continuation boundary. The 100k fixture's unfiltered middle cursor dropped from about 50k filtered rows to one; owner-filtered plan still filters about 9.5k candidates and remains an optimization follow-up, not an acceptance/SLO claim.
- `internal/e2e/worker_recovery_test.go`: starts a real API executable and two independent Worker executables against a disposable PostgreSQL DB and the authenticated temporary MinIO service. A row-lock barrier holds the success ACK after the shared artifact Put; the test kills the recorded lease owner, releases the barrier, and verifies the surviving process reclaims after lease expiry (attempt/version 2), reads/reuses the same artifact, and completes the API-visible task. Clean Evidence `wave2-20261009T143117144Z-24d8857f8d90` passed this path under the Race-enabled harness. This is deterministic development Eval recovery, not a real provider or production admission.
- `internal/config/config.go` and `internal/observability/{logger,secret_redaction}.go`: API/Worker logger instances receive configured credential values in memory and redact exact matches, sensitive attribute names, bearer strings, credential-bearing URLs and common credential `key=value` forms. Tests ensure emitted JSON has no configured secret values. This does not prove redaction for arbitrary opaque/nested data or an external log sink.

## Compatibility, rollback, and correctness

Handler result fields that identify persisted artifacts now use `artifact://<logical-key>` rather than worker-local absolute paths. Consumers must resolve those references via the configured Store, not `os.ReadFile`. The Store prefix is configured out of band. Existing LocalStore remains available for development and tests.

The new handler work has no database schema dependency; rollback is a code revert to the prior implementation checkpoint. Existing identity/audit and keyset migrations are separate pre-existing work and must not be removed as part of this rollback. Conditional writes prevent silent replacement; stale Worker fencing and task ACK remain PostgreSQL responsibilities. This is at-least-once execution, not exactly-once execution.
